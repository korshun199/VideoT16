# ARM64-лаборатория VideoT16

Лаборатория предназначена для проверки переноса VideoT16 с ноутбука x86_64 на
универсальную виртуальную ARM64-платформу перед прибытием Orange Pi 4 Pro.

Это не эмуляция Allwinner A733. QEMU проверяет архитектуру ARM64, пакеты,
запуск Python/OpenCV и совместимость файлов проекта. NPU, GPU, MIPI, GPIO,
реальные задержки и производительность Orange Pi здесь не воспроизводятся.

## Подготовка

Нужны QEMU и UEFI-прошивка ARM64:

```bash
sudo apt install qemu-system-arm qemu-efi-aarch64 qemu-utils
```

## Запуск

```bash
./arm64-lab/build
./arm64-lab/run
```

Образы и рабочий диск находятся в `images/` и не добавляются в Git.

При сборке создаётся локальный NoCloud-образ с публичным ключом
`~/.ssh/id_ed25519.pub`. Приватный ключ из компьютера не копируется.

После запуска вход выполняется так:

```bash
ssh -p 2224 debian@127.0.0.1
```

При запущенной ВМ минимальное окружение и исходники передаются командой:

```bash
./arm64-lab/provision
```

## Следующий этап

После первого запуска настраивается SSH-доступ, затем `provision` устанавливает
минимальное ARM64-окружение и запускает тест VideoT16 на записанном видео.

## Текущий результат ARM64-проверки

- Debian 12 ARM64 загрузился в QEMU;
- OpenCV, NumPy и ONNX Runtime установились;
- 23 unit-теста VideoT16 прошли успешно;
- видеопоток из 30 кадров обработан с рамкой `OBJECT` и OSD;
- ONNX Runtime загрузил военную модель и получил выход `(1, 14, 2100)`;
- OpenCV DNN 4.6 модель не загрузил из-за несовместимости оператора `Add`;
- CPU-инференс в QEMU занял около 16,6 секунды, поэтому эта цифра не является
  характеристикой Orange Pi и нужна только как базовая точка эмуляции.

## Оптимизация модели

Экспортёр находится в `scripts/export_military_onnx.py`.

```bash
./.venv/bin/python scripts/export_military_onnx.py \
  --imgsz 256 --opset 11 \
  --output arm64-lab/shared/military_vehicle_256_opset11.onnx
```

Предварительный динамический INT8-вариант создаётся так:

```bash
./.venv/bin/python scripts/quantize_onnx.py \
  arm64-lab/shared/military_vehicle_256_opset11.onnx \
  arm64-lab/shared/military_vehicle_256_int8.onnx
```

Вариант 256×256 уменьшает выход с `(1, 14, 2100)` до `(1, 14, 1344)`.
Динамический INT8 уменьшает файл примерно с 43 до 11 МБ, но сам по себе не
гарантирует ускорение и требует проверки качества на настоящих кадрах.

Для NPU A733 нужен совместимый vendor-runtime и точная пара драйвер/SDK.
QEMU эту часть не проверяет; на реальной плате сначала сверяются версии
`galcore`/TIM-VX, затем выполняется конвертация и тест двух последовательных
инференсов.
