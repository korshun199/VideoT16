# Перенос VideoT16 на Raspberry Pi

Этот файл описывает состав тестовой загрузки VideoT16 на Raspberry Pi.
Подготовка выполняется по правилам `SECURITY.md`. Сначала используется
отдельная тестовая SD-карта.

## 1. Открытая часть на SD-карте

На карту можно установить открытые системные компоненты:

```text
ОС Raspberry Pi
Python 3
OpenCV
venv и зависимости из requirements-raspberry.txt
драйверы камеры и видеовыхода
systemd-служба launcher
открытый launcher
файл активации конкретной платы
зашифрованный payload VideoT16
```

Зависимости устанавливаются на самой Raspberry Pi из интернета. `.venv` с
ноутбука не переносится.

## 2. Содержимое зашифрованного payload

В payload входят только файлы, необходимые для работы VideoT16:

```text
run_raspberry.sh

src/
  __init__.py
  displayport_proxy.py
  drm_output.py
  framebuffer_output.py
  inav_msp.py
  local_object_detection.py
  onnx_detector.py
  osd.py
  preview.py              # временный просмотр обработанного кадра
  realtime.py
  tracker.py

config/
  __init__.py
  osd_config.py
  runtime_settings.py
  runtime_settings.json

models/
  fpv_drone_latest.onnx

web_config/
  __init__.py
  index.html
  server.py
```

`models/fpv_drone_latest.onnx` — последняя модель после обучения 11.09.2026.

## 3. Что не переносится

На Raspberry Pi не переносятся:

```text
dataset/
runs/
*.pt
.venv/ с ноутбука
скрипты обучения и подготовки датасетов
фотографии, видео и локальные кэши
SECURITY.md
security/
ключи, пароли, токены и главный ключ подготовки
```

Исходники VideoT16 и модель находятся внутри зашифрованного payload и не
лежат на рабочей карте в открытом виде.

## 4. Порядок подготовки

1. Записать ОС на отдельную тестовую SD-карту.
2. Первый раз загрузить Raspberry Pi и подключить её к локальной сети.
3. Установить Python, OpenCV и зависимости из `requirements-raspberry.txt`.
4. Получить аппаратный ID платы.
5. На ноутбуке собрать payload и создать файл активации для этого ID.
6. Зашифровать payload и подготовить ARM-launcher.
7. Передать на карту только launcher, активацию и зашифрованный payload.
8. Запустить тест без камеры и проверить проверку ID и хешей.
9. Проверить отказ с подменённым ID.
10. Подключить камеру, INAV и проверить рабочий видеотракт.

## 5. Важные ограничения

- Рабочую SD-карту до завершения тестовой фазы не форматировать.
- `security/` и главный ключ не копировать на Raspberry Pi.
- Запись и установка systemd выполняются только после проверки цели.
- QEMU может проверить ARM-запуск программ, но не заменяет проверку камеры,
  UART, J7, HDMI и NPU на реальной плате.

## 7. Следующие задачи

Требует отдельной проверки на реальном оборудовании:

```text
[ ] принять и сохранить поток цифрового OSD от полётника
[ ] запустить распознавание кадра EasyCap
[ ] добавить рамку и подпись в поток цифрового OSD
[ ] вернуть обновлённый поток OSD в цифровой видеотракт
[ ] выполнить контрольную перезагрузку с автоматическим запуском
```

Текущий стабильный тест выполняется с USB Brio 90 без HDMI и J7. Рабочий
режим должен использовать EasyCap и цифровой MSP DisplayPort-прокси. Прямой
DRM-вывод HDMI на Raspberry Pi 5 не использовать.
