# Понятная памятка к `runtime_settings.json`

## Перед тем как менять файл

Сам `runtime_settings.json` оставлен обычным JSON. В этом формате нельзя
писать комментарии `//` или `/* … */`: программа читает файл строгим JSON-
парсером и перестанет запускаться, если добавить туда такие пометки. Поэтому
объяснения лежат в этой памятке рядом с файлом, а значения настроек не изменены.

Важно: в проекте есть несколько вариантов запуска, и они читают разные файлы.

- `./lcam` и `./lcam --m` запускают нынешний настольный конвейер V2. Его профиль
  находится в `config/live_drone_profiles.json`; `runtime_settings.json` на
  этот запуск не влияет.
- Старый запуск `src.local_object_detection` читает `runtime_settings.json`.
  При запуске через корневой `./cam` часть параметров явно передаётся из
  переменных окружения или значений по умолчанию и поэтому перекрывает JSON.
- В этом старом запуске сейчас действительно берутся из секции `detection`
  порог, размер обработки, интервал обработки и подпись `OBJECT`. Путь к модели,
  выбор типа камеры и большинство переключателей видеовыхода из этого файла
  автоматически не подключены: для них запуск использует аргументы командной
  строки или отдельный профиль.

Ниже у каждого пункта отмечено, что происходит **сейчас**. «Не подключено»
означает, что значение хранится в JSON и показывается редактором, но сам текущий
код запуска не применяет его автоматически. Это не ошибка формата и не повод
менять значение наугад.

## `detection` — параметры старого запуска `src.local_object_detection`

| Параметр | Сейчас | Что делает и какие значения допустимы |
|---|---:|---|
| `detection.model_path` | `models/anti_uav_fast_320_int8_pc.onnx` | Путь к файлу модели. Нужен существующий файл модели, например `.onnx` или `.pt`. **Сейчас не подключён к выбору модели при запуске:** фактическую модель задаёт аргумент `--model` (у `./cam` — переменная `VIDEOT16_MODEL` или значение внутри скрипта). |
| `detection.camera_source` | `easycap` | Тип источника. В редакторе доступны `easycap` — USB-видеозахват EasyCap — и `usb` — другая USB-камера/оцифровщик. **Автоматический выбор источника этим полем сейчас не выполняется.** |
| `detection.digital_camera_device` | `""` (пусто) | Адрес/имя цифровой камеры или устройства захвата. Обычно это путь устройства, например `/dev/video0` или `/dev/v4l/by-id/...`; пустое значение означает «не выбрано». **Сейчас не используется для открытия камеры.** |
| `detection.confidence_percent` | `35` | Минимальная уверенность модели в процентах: чем выше, тем строже фильтр и тем меньше ложных рамок, но можно пропустить слабое распознавание. При сохранении файла разрешено **1–100**. Вступает в силу в старом запуске, если порог не был явно задан аргументом запуска. |
| `detection.inference_size` | `320` | Размер стороны изображения, которое передаётся модели для распознавания; исходный кадр камеры от этого не меняет размер. Больше — потенциально лучше видны мелкие объекты, но выше нагрузка и задержка. При сохранении разрешено **32–1280**; на практике выбирают поддерживаемый моделью размер, обычно `320` или `640`. Фиксированную форму входа ONNX-модели менять этим числом нельзя. |
| `detection.inference_interval` | `1` | Сколько кадров камеры пропускать между запусками распознавания. `1` — распознавать каждый кадр; `2` — каждый второй и т. д. Большое число снижает нагрузку, но обновляет рамку реже. При сохранении разрешено **1–30**. |
| `detection.generic_label` | `false` | Подпись рамки: `false` — имя класса из модели; `true` — вместо него писать `OBJECT`. Возможны только `true` или `false`. В старом запуске применяется. |

## `desktop` — сохранённые параметры настольной камеры

В текущем коде `src.local_object_detection` этот блок сам по себе не выбирает
камеру, модель, разрешение или частоту. Корневой `./cam` получает такие значения
из `VIDEOT16_*` и передаёт их программе отдельно. Значения ниже — то, что сейчас
записано в JSON, а не гарантия активного режима камеры.

| Параметр | Сейчас | Что означает и диапазон |
|---|---:|---|
| `desktop.camera_device` | `/dev/video0` | Путь к камере/USB-оцифровщику. При сохранении проверяется только, что это непустая строка; на Linux обычно `/dev/videoN` или `/dev/v4l/by-id/...`. Устройство должно реально существовать. |
| `desktop.model_path` | `models/anti_uav_fast_320_int8_pc.onnx` | Путь к модели настольного распознавания. При сохранении проверяется только, что строка не пустая; файл должен существовать, когда именно эта модель будет передана программе при запуске. Текущий `./lcam` читает `live_drone_profiles.json`, а `./cam` — переменную `VIDEOT16_MODEL` или значение внутри скрипта; этот пункт JSON автоматически не применяют. |
| `desktop.confidence_percent` | `30` | Порог уверенности для настольного запуска, в процентах. Проверка при сохранении: **1–100**. Этот блок текущий запуск автоматически не читает. |
| `desktop.inference_size` | `640` | Сторона входа для модели в пикселях. Проверка при сохранении: **32–1280**; размер должен быть совместим с самой моделью. Этот блок текущий запуск автоматически не читает. |
| `desktop.inference_interval` | `1` | Частота обработки относительно кадров камеры: `1` — каждый кадр, `2` — каждый второй и т. д. Проверка при сохранении: **1–30**. Этот блок текущий запуск автоматически не читает. |
| `desktop.capture_width` | `1280` | Желаемая ширина захватываемого кадра, в пикселях. Проверка при сохранении: **32–7680**. Реальное устройство может не поддерживать выбранный размер. Этот блок текущий запуск автоматически не читает. |
| `desktop.capture_height` | `720` | Желаемая высота захватываемого кадра, в пикселях. Проверка при сохранении: **32–7680**. Ширину и высоту надо выбирать парой из режимов, которые поддерживает камера. Этот блок текущий запуск автоматически не читает. |
| `desktop.camera_fps` | `60` | Желаемая частота захвата, кадров в секунду. Проверка при сохранении: **1–120 FPS**. Камера может согласиться только на близкий поддерживаемый режим; число в файле не гарантирует реальный FPS. Этот блок текущий запуск автоматически не читает. |
| `desktop.clean_window` | `true` | Просьба показывать чистое окно без служебных панелей. Возможны `true`/`false`. В корневом `./cam` аналогичный режим включается через `VIDEOT16_CLEAN_WINDOW`, а не из этого поля JSON. |

## `video_output` — выводы и веб-просмотр

Переключатели и адреса в этой таблице **не включают физические выходы сами по
себе**. В текущем старом запуске код читает из этого блока только частоты
обновления веб-предпросмотра и цифрового OSD — и только если соответствующий
выход уже запущен аргументами командной строки. Для работы с J7, UART или DRM
не меняйте эти строки наугад: текущий запуск управляется отдельными аргументами.

| Параметр | Сейчас | Что означает и возможные значения |
|---|---:|---|
| `video_output.j7_enabled` | `false` | Предполагаемый общий переключатель аналогового выхода J7. `true`/`false`. **Автоматически не подключён; изменение JSON само по себе J7 не включает.** |
| `video_output.j7_overlay_enabled` | `false` | Предполагается, что включает графическое наложение на J7. `true`/`false`. **Автоматически не подключён.** |
| `video_output.flight_controller_osd_enabled` | `false` | Предполагаемый переключатель штатного OSD/данных полётного контроллера. `true`/`false`. **Автоматически не подключён.** |
| `video_output.drm_device` | `/dev/dri/card1` | Путь к DRM/KMS-видеоустройству Linux. Обычно `/dev/dri/cardN` или стабильный путь из `/dev/dri/by-path/`. **Из JSON сейчас не читается**; устройство задаётся параметром `--drm`. |
| `video_output.flight_controller_port` | `/dev/ttyACM0` | Имя последовательного порта контроллера, обычно `/dev/ttyACM0` или `/dev/ttyUSB0`. **Из JSON сейчас не читается**; порт задаётся отдельным параметром запуска. |
| `video_output.preview_fps` | `5.0` | Максимальная частота обновления веб-предпросмотра, кадров/с. Проверка при сохранении: **1–25 FPS**. Применяется только если веб-предпросмотр уже запущен через параметр `--preview-port`. |
| `video_output.displayport_osd_fps` | `1.0` | Частота обновления добавочного цифрового OSD, кадров/с. Проверка при сохранении: **0.2–10 FPS**. Применяется только если цифровое OSD уже запущено через UART-аргументы командной строки. Это частота обновления OSD, не частота видеокадров и не FPS распознавания. |
| `video_output.displayport_proxy_enabled` | `true` | Предполагается, что включает цифровой OSD-прокси. `true`/`false`. **Сейчас этот флаг не используется для запуска прокси**; нужны отдельные UART-аргументы. |
| `video_output.displayport_fc_port` | `/dev/ttyAMA0` | UART со стороны полётного контроллера. Путь устройства, например `/dev/ttyAMA0` или `/dev/ttyUSB0`. **Из JSON сейчас не читается**; порт передаётся аргументом запуска. |
| `video_output.displayport_vtx_port` | `/dev/ttyAMA2` | UART со стороны видеопередатчика. Путь устройства, например `/dev/ttyAMA2` или `/dev/ttyUSB0`. **Из JSON сейчас не читается**; порт передаётся аргументом запуска. |
| `video_output.displayport_vtx_only` | `false` | Предполагает режим, где собственное OSD отправляется только передатчику, без входа от полётника. `true`/`false`. **Из JSON сейчас не читается**; соответствующий режим задаётся отдельным аргументом запуска. |
| `video_output.preview_enabled` | `true` | Предполагаемый выключатель веб-просмотра. `true`/`false`. **В текущем коде не проверяется**: веб-просмотр включается наличием `--preview-port`. |
| `video_output.preview_host` | `127.0.0.1` | Адрес, на котором предполагается открыть веб-просмотр. Это IP-адрес или имя сетевого интерфейса. `127.0.0.1` доступен только на этом же компьютере; `0.0.0.0` обычно открывает доступ со всех сетей и требует осторожности. **Сейчас берётся аргумент `--preview-host`, а не JSON.** |
| `video_output.preview_port` | `8081` | Предполагаемый сетевой порт веб-просмотра, целое число **1–65535**; `0` обычно означает «не запускать» в аргументах программы. **Сейчас берётся аргумент `--preview-port`; значение JSON не включает сервер.** |

## `horizon` — искусственный горизонт

Линия появляется только если в телеметрии есть одновременно крен и тангаж.
Расстояния — в пикселях, тангаж — в градусах, цвета — RGB с компонентами
**0–255**.

| Параметр | Сейчас | Что делает и диапазон |
|---|---:|---|
| `horizon.pitch_scale` | `4.0` | На сколько пикселей линия смещается на каждый градус тангажа. Положительное число; обычно **1–10 пикселей/градус**. |
| `horizon.pitch_limit` | `45.0` | Максимальный тангаж, учитываемый при смещении линии, в градусах. Положительное число; обычно **10–90°**. |
| `horizon.min_length` | `240` | Минимальная длина линии горизонта, пиксели; целое положительное. |
| `horizon.length_ratio` | `0.5` | Доля короткой стороны кадра, задающая длину линии, если она больше `min_length`. Обычно **0.1–1.0**; при значении выше `1` линия может выходить за границы. |
| `horizon.thickness` | `1` | Толщина цветной линии горизонта, пиксели; целое положительное, обычно **1–5**. |
| `horizon.color_rgb` | `[255,255,0]` | Цвет линии RGB; сейчас жёлтый. Три целых компонента **0–255**. |
| `horizon.shadow_color_rgb` | `[0,0,0]` | Цвет контурной подложки RGB; сейчас чёрный. Три целых компонента **0–255**. |
| `horizon.shadow_thickness` | `3` | Толщина тёмной подложки под линией, пиксели; целое положительное, обычно больше `thickness`. |

## Как понимать числа и цвета

- Размеры, толщины и отступы оформления указаны в **пикселях исходного кадра**,
  а не в сантиметрах и не обязательно в пикселях экрана после масштабирования.
- Цвет записывается как `[R, G, B]`: сначала красный, затем зелёный, затем синий.
  Каждое число — целое от `0` до `255`. Примеры: красный `[255,0,0]`, зелёный
  `[0,255,0]`, синий `[0,0,255]`, жёлтый `[255,255,0]`, белый `[255,255,255]`,
  чёрный `[0,0,0]`.
- Программа при сохранении проверяет диапазоны порогов, размеров/частоты захвата,
  частот предпросмотра и OSD, булевы переключатели и компоненты цветов. Для
  большинства декоративных размеров отдельной строгой проверки нет: используйте
  указанные практические границы и меняйте по одному параметру.
- В файле нет секции `camera`. При чтении программа дополняет её значениями из
  `config/runtime_settings.py`; сейчас среди них по умолчанию выключена отправка
  ручных V4L2-регуляторов (`v4l2_controls_enabled: false`).
