# Нативный редактор настроек VideoT16

`editor.py` — отдельное настольное приложение на Qt. Оно открывает настоящее
окно, не запускает браузер и не поднимает HTTP-сервер.

## Запуск на Linux

В установленном проекте редактор запускается двойным щелчком по ярлыку
`VideoT16 — настройки` на рабочем столе. Ярлык запускает
`/home/work/VideoT16/config/editor.py` через Python из `.venv` проекта.
Для окна требуется PySide6; зависимость описана отдельно в
`requirements-editor.txt`, чтобы не добавлять Qt в окружение распознавания без
необходимости.

Если Qt ещё не установлен в окружение проекта, из корня VideoT16 один раз
выполняется:

```bash
./.venv/bin/python -m pip install -r requirements-editor.txt
```

Пользователь выбирает JSON-файл и меняет поддерживаемые параметры мышью:
переключатели, ползунки, списки и палитру цветов. Поля без безопасного
элемента выбора остаются только для чтения. Изменения сохраняются в выбранный
файл каталога `config/`; копии и резервные файлы редактор не создаёт.
Перед сохранением проверяется формат JSON и контрольная сумма исходного файла,
чтобы не затереть более свежие внешние изменения. Настройки применяются при
следующем запуске системы распознавания.

Для `runtime_settings.json` кнопка «По умолчанию» подставляет значения из
`config/runtime_settings.py` (`DEFAULT_SETTINGS`), включая настольный порог
50% и частоту камеры 55 FPS. Она не записывает файл сама: для применения
значений нужно отдельно нажать «Сохранить настройки». Если сброс включит
выключенные видеовыходы J7 или OSD полётника, редактор сначала покажет
предупреждение. Дополнительные поля, которых нет в наборе программных значений,
сохраняются. Для других JSON-файлов кнопка отключена, поскольку у них нет общего
набора значений по умолчанию.

## Проверка

Тесты запускаются в проектном окружении без монитора:

```bash
QT_QPA_PLATFORM=offscreen ./.venv/bin/python -m unittest discover -s tests -p 'test_config_editor.py' -v
```

Обычный `./lcam` сразу запускает сохранённый профиль `sky`. Окно настроек
этого же профиля открывается только по `./lcam --m`; после выбора параметров
кнопка запуска сохраняет конфигурацию и запускает распознавание.

## Живой прототип компенсации движения

Для экспериментов с маленьким тёмным объектом на земле создан отдельный файл
`motion_trial.json`. Он остаётся самостоятельным стендом для показа маски
движения. Старый режим `./lcam` использует профиль `sky` из
`live_drone_profiles.json`; его секция `two_stage` включает быстрый поиск
кандидата перед YOLO. Вычисления вынесены в отдельный фоновый поток, поэтому
он не ждёт отрисовку. Режим не меняет видеотракт.

### Проверка базового конвейера V2

`./lcam --m` открывает Qt-меню с файлом `live_drone_profiles.json` и профилем
`sky`. Модель, параметры задержки, буфера, рамки, захвата и окна меняются в
этом окне; кнопка запуска сохраняет конфигурацию и запускает тот же профиль.
`./lcam` без аргументов запускает профиль напрямую, без Qt-меню.

Редактор перечисляет только фиксированные квадратные ONNX-модели, читает
размер входа каждой модели из её метаданных и показывает его в списке. Размер
входа ONNX задаётся самой моделью, а не полем захвата. Режимы разрешения и FPS
берутся отдельно у выбранного V4L2-устройства командой `v4l2-ctl`; меню
показывает только поддерживаемые камерой комбинации. При отсутствии списка
режимов запуск V2 блокируется, чтобы не отправить камере неподтверждённый
режим. Для этого редактора `onnx` устанавливается из `requirements-editor.txt`.

Параметры конвейера читаются из `profiles.sky.pipeline_v2`. Схема разделена на три независимых этапа:

1. Поток захвата нумерует кадр, кладёт его в буфер вывода и тот же пакет с тем же
   ID — в mailbox распознавания.
2. Поток YOLO забирает задание; результаты хранятся с ID исходного кадра,
   количеством детекций и временем обработки.
3. Окно читает цветные кадры из отложенного буфера строго по ID и показывает
   последнюю подходящую рамку YOLO. Рамка ограниченно удерживается, без
   оптического трекера, который мог терять маленькие или малоконтрастные объекты.
   Пилотский видеотракт не меняется.

Основные параметры V2:

- `display_fps` — ограничение частоты обновления окна;
- `output_delay_ms` — задержка только локального окна относительно входного потока;
- `output_buffer_max_mb` — жёсткий предел памяти для цветных кадров;
- `box_hold_ms` — максимальный срок удержания последней обнаруженной рамки на
  задержанном выходном кадре;
- `output_delay_ms` — запас времени, чтобы ответы для следующих кадров успели
  попасть в буфер и рамку можно было привязать к тому кадру, который выводится.
- `pipeline_v2.max_match_distance_fraction` — максимально допустимое смещение центра
  рамки между соседними ответами YOLO для интерполяции.

Начальная задержка выбрана 2200 мс при пределе буфера 512 МиБ. Журнал раз в
секунду фиксирует ID последнего захваченного кадра, диапазон ID в видеобуфере,
ID кадра на входе и выходе YOLO, число детекций/рамок выше порога, ID кадра на
экране и ID источника рамки. Клавиша `R` включает и выключает YOLO, `Q` или
`Esc` закрывает окно. Журнал создаётся в
`test_samples/video_trials/logs/live_pipeline_v2_*.log`.

### Двухступенчатый режим старого `lcam`

В `profiles.sky.two_stage` находятся все параметры новой схемы:

1. `roi_*` задают центральную зону быстрого поиска. Начальное значение 50×50%
   даёт четверть площади кадра.
2. `motion_*` управляют компенсацией движения фона и отбором изменившихся
   областей. Они не утверждают, что найден дрон, а только создают кандидата.
3. `candidate_crop_size` и `candidate_padding` задают вырез вокруг кандидата,
   который один раз проверяется YOLO. Координаты рамки затем переносятся обратно
   в полный кадр.
4. `full_scan_interval_ms` задаёт редкий обход всех плиток как страховку, если
   быстрый модуль не увидел движения.
5. `max_detection_age_ms` запрещает рисовать результат по уже другому кадру.
   Поэтому при перегрузке кадр остаётся живым, но старая рамка исчезает, а не
   уезжает за объектом.

Стартовые значения: один кандидат, вырез 640 пикселей, полный обход раз в 1500
мс при отсутствии кандидата и возраст рамки не более 300 мс. Все изменения
вступают в силу при следующем запуске `./lcam`.

Запуск:

1. Из корня проекта открыть окно: `./lcam2`.
2. В списке **Файл настроек** выбрать `motion_trial.json`.
3. Настроить камеру, разрешение/FPS, размер и положение центральной области,
   пороги яркости/цвета, модель, порог YOLO и оформление окна.
4. Нажать **Запуск распознавания**. Настройки сохранятся в выбранный JSON;
   окно редактора закроется, а изображение откроет отдельный процесс `lcam3`.
5. `Esc` или `Q` закрывает окно и останавливает прототип. Без окна можно выбрать
   `display.output_device = none`; тогда процесс останавливается через `Ctrl+C`.

Параметры, включая выбранный USB-видеовход, находятся в
`config/motion_trial.json`; форма Qt строится из этого JSON и позволяет менять
все числовые, логические, цветовые и перечисляемые параметры мышью. Значение
`detector.threads = 0` означает все доступные логические ядра для ONNX Runtime;
OpenCV имеет отдельный ограничитель `motion.opencv_threads`.
`display.output_device` выбирает только локальное окно монитора или запуск без
окна; J7, UART, видеопередатчик и видеотракт дрона прототип не открывает и не
меняет.

Алгоритм сначала обрезает заданную область кадра (по умолчанию центральные
50% ширины и 50% высоты — четверть площади), сопоставляет точки фона между
соседними кадрами через optical flow + RANSAC и компенсирует общий перенос и
поворот камеры. Затем ищет остаточную разницу яркости в Lab и отдельно — цветовую
разницу; общая перемена экспозиции удаляется медианой. По желанию можно подавлять
светлые малонасыщенные блики. Видеозахват хранит только последний кадр, поэтому
медленный YOLO не выстраивает очередь кадров и не задерживает отдельную оранжевую
рамку движения.

Интерпретация экрана:

- `MOVE?` / оранжевая рамка — только кандидат по движению и цвету, не утверждение,
  что это дрон;
- `YOLO` / зелёная рамка — отдельный результат выбранной модели;
- маленькая вставка показывает ROI с подсвеченной маской движения;
- `BG=OK` означает, что общий сдвиг фона оценён и вычтен; `BG=RAW` — кадры
  сравниваются без компенсации, потому что точек фона не хватило или сдвиг вышел
  за настроенный предел.

Журнал создаётся в каталоге из `diagnostics.log_dir` (по умолчанию
`logs/motion_trials/`) с измеренными разрешением/FPS/FourCC, скоростью цикла,
уверенностью YOLO, числом изменившихся пикселей, сдвигом фона и координатами
кандидатов. В журнал не записываются кадры или видео.

Ограничения первого прототипа: движение камеры и динамичный фон могут давать
ложные кандидаты; объект почти без текстурного/яркостного отличия от земли может
не дать сигнала; смазанное изображение снижает качество оценки фона. Поэтому
`MOVE?` — сигнал для испытаний и настройки, а не готовая система сопровождения
или команда управления дроном. Проверки сейчас синтетические; поведение на живом
потоке ещё требует отдельного пользовательского запуска.
