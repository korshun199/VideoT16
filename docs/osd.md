# Руководство по OSD

## Что такое OSD в этом проекте

OSD здесь — это программный слой поверх изображения с камеры. Ноутбук
одновременно получает кадр камеры, читает телеметрию полётного контроллера INAV
по USB/MSP и рисует текст, рамки объектов и искусственный горизонт.

```text
камера + YOLO ──────┐
                    ├─> кадр с OSD ─> HDMI-монитор
INAV ── USB/MSP ────┘
```

Это не штатное OSD видеопередатчика и не команда управления полётником. Текущий
читатель INAV работает только в режиме чтения.

## Быстрый запуск

```bash
cd /home/work/VideoT16
source .venv/bin/activate

python3 -m src.detection \
  --source /dev/video0 \
  --model models/military_vehicle_best.pt \
  --inav-port /dev/ttyACM0 \
  --confidence 0.50 \
  --generic-label \
  --resolution 1920x1080 \
  --window-x 1920 \
  --window-y 0 \
  --fullscreen
```

Без параметра `--inav-port` распознавание камеры будет работать, но OSD INAV
не появится.

## Какие данные уже получаем

Данные читаются классом `InavMspReader` в файле
[`src/msp.py`](../src/msp.py).

| Данные | Поле программы | Сейчас на экране |
|---|---|---|
| Версия INAV | `variant`, `version` | Да |
| Крен | `roll` | Да, строка `R` |
| Тангаж | `pitch` | Да, строка `P` и горизонт |
| Курс | `yaw` | Да, строка `Y` |
| Высота | `altitude` | Да |
| Напряжение батареи | `voltage` | Да |
| RSSI | `rssi` | Да, в процентах |
| GPS fix | `gps_fix` | Да |
| Спутники | `gps_satellites` | Да |
| Широта | `latitude` | Получаем, пока не показываем |
| Долгота | `longitude` | Получаем, пока не показываем |
| Флаги режимов | `mode_flags` | Получаем, пока не расшифровываем |

Если GPS не подключён или не получил координаты, ожидаемы значения `fix 0` и
`SAT 0`. Если приёмник не подключён, RSSI может быть равен нулю.

## Как данные попадают на изображение

Основной файл —
[`src/detection.py`](../src/detection.py).

### Текстовая телеметрия

Функция `draw_telemetry()` собирает строки INAV и передаёт их в
`put_osd_text()`.

```python
lines.append(f"ALT {telemetry.altitude:.2f} m")
```

Чтобы вывести уже имеющееся поле, например координаты, добавляется строка:

```python
if telemetry.latitude is not None and telemetry.longitude is not None:
    lines.append(f"GPS {telemetry.latitude:.6f} {telemetry.longitude:.6f}")
```

Цвета, шрифт, размер, толщину и расположение менять в основном коде не нужно.
Они находятся в [`config/display.py`](../config/display.py).

### Искусственный горизонт

Функция `draw_artificial_horizon()` использует:

- `roll` — поворачивает полоску горизонта;
- `pitch` — сдвигает полоску вверх или вниз;
- `AXIS_STYLE` — рисует неподвижную центральную ось.

Горизонт является визуальным индикатором ориентации, а не навигационным
прибором. Направление и масштаб следует проверять на реальном полётнике.

### Рамки объектов

Функция `draw_detections()` рисует рамку объекта и подпись с уверенностью
модели, например:

```text
OBJECT 85%
```

Стиль рамки и подписи настраивается в `OBJECT_STYLE`.

## Настройка внешнего вида

Все визуальные параметры собраны в
[`config/display.py`](../config/display.py).

### Цвета OpenCV

OpenCV использует порядок BGR, а не привычный RGB:

```python
"color": (0, 255, 255)       # жёлтый
"color": (0, 255, 0)         # зелёный
"color": (255, 255, 255)     # белый
"color": (255, 0, 0)         # синий
"color": (0, 0, 255)         # красный
"color": (0, 0, 0)           # чёрный
```

### Основные группы настроек

`OSD_TEXT`:

- `font` — имя шрифта OpenCV;
- `font_scale` — размер текста;
- `color` — цвет текста;
- `shadow_color` — цвет тени;
- `thickness` — толщина текста;
- `shadow_thickness` — толщина тени;
- `shadow_offset` — смещение тени вправо и вниз;
- `left`, `top` — положение первой строки;
- `line_spacing` — расстояние между строками.

`OBJECT_STYLE`:

- `color` — цвет рамки и подписи объекта;
- `box_thickness` — толщина рамки;
- `font`, `font_scale` — шрифт подписи;
- `text_thickness` — толщина подписи;
- `text_offset_y` — расстояние подписи от рамки.

`FLIGHT_STATUS_STYLE`:

- `right`, `top` — положение блока `ARM` и `THR`;
- `line_spacing` — расстояние между двумя строками;
- `bar_top_offset`, `bar_width`, `bar_height` — положение и размер шкалы газа;
- `bar_color`, `fill_color` — цвет рамки и заполнения;
- `marker_color`, `marker_overhang` — цвет и ширина подвижного маркера;
- параметры `shadow_*` — чёрная контрастная окантовка шкалы и маркера.

`HORIZON_STYLE`:

- `pitch_scale` — чувствительность смещения по тангажу;
- `pitch_limit` — максимальное отображаемое смещение;
- `min_length` — минимальная длина горизонта;
- `length_ratio` — доля меньшей стороны кадра;
- `color`, `thickness` — цвет и толщина линии;
- `shadow_color`, `shadow_thickness` — её подложка.

`AXIS_STYLE`:

- `vertical_half_length` — половина длины вертикальной оси;
- `horizontal_half_length` — половина ширины центральных крыльев;
- `color`, `thickness` — цвет и толщина оси;
- `shadow_color`, `shadow_thickness` — её подложка.

После изменения настроек программу нужно перезапустить.

Для автоматического вывода на конкретный X11-монитор используется его имя из
`xrandr`, например:

```bash
./run_modeling.sh --monitor HDMI-1 -p 50
```

При выборе `--monitor` программа сама использует текущее разрешение и координаты
этого экрана. Параметры `--resolution`, `--window-x` и `--window-y` для такого
запуска вручную задавать не требуется.

## Какие данные можно добавить в будущем

Официальный протокол INAV MSP предоставляет значительно больше данных, чем
используется сейчас. В текущем коде уже заложена основа для следующих групп:

| Группа | Возможные данные |
|---|---|
| GPS | широта, долгота, высота, скорость, курс над землёй |
| Домой | расстояние до Home, направление на Home |
| Навигация | режим навигации, состояние RTH, активная задача |
| Батарея | ток, потребление, оставшийся заряд, число аккумуляторов |
| Датчики | акселерометр, гироскоп, магнитометр, барометр |
| Управление | значения RC-каналов, активные AUX-режимы |
| Выходы | значения сервоприводов и моторов |
| Состояние | активные режимы полёта, failsafe, состояние GPS |

Не все поля доступны на каждом полётнике: это зависит от версии INAV,
подключённых датчиков, настроек портов и наличия GPS/приёмника.

В документации INAV команды `MSP_RAW_GPS`, `MSP_ATTITUDE`, `MSP_ALTITUDE` и
`MSP_ANALOG` описаны как команды выдачи телеметрии. В новых версиях INAV часть
старых команд помечена устаревшими, поэтому при переносе на Orange Pi следует
проверить соответствующие MSP2-команды.

Полезные официальные источники:

- [INAV Serial](https://github.com/iNavFlight/inav/blob/master/docs/Serial.md)
- [INAV MSP extensions](https://github.com/iNavFlight/inav/blob/master/docs/API/MSP_extensions.md)
- [MSP protocol definitions](https://github.com/iNavFlight/inav/blob/master/src/main/msp/msp_protocol.h)

## Как добавить новое поле

Порядок работы:

1. Добавить поле в `InavTelemetry` в `src/msp.py`.
2. Добавить MSP-команду в список `_commands`.
3. Разобрать payload в `_decode()` с проверкой длины пакета.
4. Добавить строку в `draw_telemetry()` или графический элемент в отдельную
   функцию.
5. Добавить внешний вид элемента в `config/display.py`.
6. Проверить на стенде без пропеллеров и убедиться, что читатель не отправляет
   команд изменения настроек.

Пример архитектуры:

```python
# src/msp.py
self.telemetry.current = ...

# src/detection.py
if telemetry.current is not None:
    lines.append(f"CUR {telemetry.current:.1f} A")
```

Настроечный файл отвечает за внешний вид, а `src/msp.py` — за получение
данных. Это разделение позволяет менять красоту OSD без вмешательства в
протокол и распознавание.

## Ограничения и безопасность

- OSD отображает полученные данные, но не исправляет их достоверность.
- Отсутствие GPS не означает неисправность камеры или модели.
- RSSI без приёмника не является показателем качества видеосвязи.
- Текущий MSP-читатель не отправляет команды управления.
- При работе с реальным аппаратом пропеллеры должны быть сняты.
- Перед переносом на Orange Pi нужно отдельно проверить нагрузку CPU, память,
  разрешение камеры и задержку изображения.

## Полный практический каталог телеметрии INAV

Этот раздел перечисляет данные, которые программа может получать от INAV по
MSP/MSPv2. Это именно каталог чтения телеметрии: команды изменения настроек,
калибровки, записи во флеш-память и управления аппаратом сюда не относятся.

Наличие конкретного поля зависит от версии INAV, включённого датчика,
настройки порта и состояния аппарата. Если датчика нет, INAV обычно возвращает
ноль, пустое значение или признак недоступности.

### Как программа получает телеметрию

Основной способ — циклический опрос:

1. программа отправляет запрос MSP;
2. полётник возвращает пакет с данными;
3. программа проверяет размер и контрольную сумму;
4. значения сохраняются в телеметрии;
5. нужные значения выводятся текстом, числом, шкалой, индикатором или
   графическим элементом.

Есть три полезных семейства сообщений:

| Семейство | Назначение |
|---|---|
| Классический MSP | Основные данные совместимости и старые команды телеметрии |
| MSPv2 INAV | Расширенные данные конкретно для INAV |
| MSPv2 SENSOR | Унифицированные данные датчиков: GPS, барометр, компас и другие |

### Идентификация и состояние контроллера

| Метод | Что можно получить | Зачем нужно |
|---|---|---|
| `MSP_API_VERSION` | Версию API MSP | Понять, какие сообщения поддерживаются |
| `MSP_FC_VARIANT` | Вариант прошивки, например `INAV` | Проверить, что подключён нужный контроллер |
| `MSP_FC_VERSION` | Версию прошивки | Выбрать совместимый формат пакетов |
| `MSP_UID` | Уникальный идентификатор платы | Различать несколько контроллеров |
| `MSP_STATUS` | Время цикла, ошибки I2C, статус датчиков, активные режимы, профиль | Быстро понять общее состояние |
| `MSP_STATUS_EX` | Загрузка системы, расширенные флаги армирования и калибровки | Диагностика перед запуском |
| `MSP2_INAV_STATUS` | Расширенный статус INAV и полные флаги режимов | Современная замена старого статуса |
| `MSP_SENSOR_STATUS` | Состояние гироскопа, акселерометра, компаса, барометра, GPS, дальномера и оптического потока | Показать, какие датчики реально работают |
| `MSP_LOOP_TIME` | Время цикла управления | Контролировать задержку и нагрузку |
| `MSP_RTC` | Секунды и миллисекунды реального времени | Записывать события с временными метками |

### Положение и ориентация

| Метод | Поля | Что показывать оператору |
|---|---|---|
| `MSP_ATTITUDE` | `roll`, `pitch`, `yaw` | Крен, тангаж, курс, искусственный горизонт |
| `MSP_RAW_IMU` | Сырые акселерометр, гироскоп и магнитометр | Диагностика датчиков, не готовая ориентация |
| `MSP_SENSOR_ALIGNMENT` | Ориентация осей ACC, GYRO и MAG | Проверка монтажа и направления платы |
| `MSP2_INAV_FULL_LOCAL_POSE` | Крен, тангаж, курс, позиция по трём осям, скорость по трём осям | Полный локальный навигационный HUD |
| `MSP2_SENSOR_COMPASS` | `magX`, `magY`, `magZ` и время измерения | Направление магнитного поля и диагностика компаса |

`MSP_ATTITUDE` подходит для нашего текущего горизонта. Сырые значения IMU
нельзя без обработки выдавать как угол: их используют для диагностики или
отдельного алгоритма фильтрации.

### Высота, скорость и вертикальное движение

| Метод | Поля | Зачем нужно |
|---|---|---|
| `MSP_ALTITUDE` | Высота, вариометр | Высота и скорость набора/снижения |
| `MSP_SONAR_ALTITUDE` | Высота над поверхностью от дальномера | Полёт возле земли |
| `MSP2_SENSOR_BAROMETER` | Давление, температура, время измерения | Барометрическая высота и диагностика |
| `MSP2_SENSOR_RANGEFINDER` | Качество, расстояние в миллиметрах | Точная высота над препятствием |
| `MSP2_INAV_AIR_SPEED` | Воздушная скорость и связанные значения | Отличать скорость относительно воздуха от GPS-скорости |
| `MSP2_SENSOR_AIRSPEED` | Дифференциальное давление, температура | Датчик воздушной скорости |
| `MSP2_INAV_WIND` | Оценка направления и скорости ветра | Поправка навигации и отображение ветра |

### GPS и навигация

| Метод | Поля | Зачем нужно |
|---|---|---|
| `MSP_RAW_GPS` | Тип фикса, число спутников, широта, долгота, высота, скорость, курс, HDOP | Основной GPS-экран |
| `MSP_COMP_GPS` | Расстояние до Home, направление на Home, heartbeat GPS | Стрелка домой и дистанция |
| `MSP_GPSSVINFO` | Спутники, номера, уровень сигнала, азимут и высота | Подробная диагностика GPS |
| `MSP_GPSSTATISTICS` | Статистика качества GPS и приёма | Поиск проблем с антенной и спутниками |
| `MSP_NAV_STATUS` | Режим навигации, состояние, активная точка, ошибка, целевой курс | Навигационный статус и RTH |
| `MSP_WP` | Номер точки, координаты, высота и флаги | Отображение текущей точки маршрута |
| `MSP2_SENSOR_GPS` | Тип фикса, спутники, точность позиции и скорости, HDOP, координаты, MSL-высота, скорости N/E/D, курс, истинный yaw, дата и время | Современный подробный пакет GPS |
| `MSP2_INAV_SAFEHOME` | Данные безопасной точки Home | Контроль навигационной зоны, если функция включена |
| `MSP2_ADSB_VEHICLE_LIST` | Список обнаруженных воздушных судов ADS-B | Воздушная обстановка при наличии ADS-B |

GPS-пакет MSPv2 может содержать точность горизонтального и вертикального
положения, точность скорости, составляющие скорости на север/восток/вниз,
курс и истинный курс. Это позволяет сделать не только `GPS 10 SAT`, но и
полноценную навигационную панель.

### Батарея и питание

| Метод | Поля | Зачем нужно |
|---|---|---|
| `MSP_ANALOG` | Напряжение, израсходованные mAh, RSSI, ток | Совместимый старый пакет батареи |
| `MSP_BATTERY_STATE` | Состояние батареи для совместимых видеосистем | Передача батарейных данных в видеосистему |
| `MSP2_INAV_ANALOG` | Флаги батареи, напряжение, ток, мощность, mAh, mWh, остаточная ёмкость, процент, RSSI | Полный современный экран питания |
| `MSP2_INAV_MISC2` | Время работы, время полёта, процент газа, признак автоматического газа | Таймеры и состояние управления тягой |
| `MSP2_INAV_BATTERY_CONFIG` | Число банок, пределы напряжения, ёмкость и пороги | Это настройки и справочные пределы, а не текущая телеметрия |

Единицы особенно важно подписывать на экране: напряжение — V, ток — A,
мощность — W, ёмкость — mAh или mWh, RSSI — шкала INAV, которую нужно
нормализовать согласно используемому пакету.

### Приёмник и управление

| Метод | Поля | Зачем нужно |
|---|---|---|
| `MSP_RC` | Значения каналов RC | Показать стики, газ и AUX |
| `MSP_ACTIVEBOXES` | Активные флаги режимов | Узнать, включены ли ANGLE, NAV, RTH и другие режимы |
| `MSP_BOXNAMES` | Имена доступных режимов | Подписать флаги понятными названиями |
| `MSP_BOXIDS` | Постоянные идентификаторы режимов | Связать флаги с именами |
| `MSP2_INAV_GET_LINK_STATS` | RSSI uplink, качество канала, SNR | Современная диагностика радиолинии |
| `MSP2_INAV_GLOBAL_FUNCTIONS` | Состояние глобальных функций | Отображение пользовательских автоматизаций |
| `MSP2_INAV_LOGIC_CONDITIONS_STATUS` | Значения логических условий | Диагностика сложной автоматики |

Получение RC-каналов — это чтение. Отдельные команды `MSP_SET_RAW_RC` и
`MSP2_INAV_SET_AUX_RC` уже относятся к передаче команд и в наш безопасный
телеметрический читатель добавляться не должны.

### Моторы, сервоприводы и силовая установка

| Метод | Поля | Зачем нужно |
|---|---|---|
| `MSP_MOTOR` | Текущие значения выходов моторов | Контроль выходов без подключения осциллографа |
| `MSP_SERVO` | Текущие значения сервоканалов | Проверка рулевых поверхностей |
| `MSP_SERVO_CONFIGURATIONS` | Конфигурация каналов сервоприводов | Справочная информация о выходах |
| `MSP2_INAV_ESC_RPM` | Обороты ESC | Контроль оборотов и пропеллеров |
| `MSP2_INAV_ESC_TELEM` | Телеметрия ESC: обороты, напряжение, ток, температура и ошибки, если ESC это передаёт | Диагностика силовой установки |
| `MSP2_INAV_OUTPUT_MAPPING` | Назначение выходов | Понять, какой физический выход за что отвечает |

Эти данные полезны для сервисного экрана, но значения моторов и сервоприводов
не следует использовать как единственный признак того, что аппарат безопасен.

### Датчики специального назначения

| Метод | Поля | Зачем нужно |
|---|---|---|
| `MSP2_INAV_OPTICAL_FLOW` | Качество, скорость потока по X/Y, скорость движения корпуса | Полёт в помещении и удержание позиции |

| `MSP2_SENSOR_COMPASS` | Магнитное поле по трём осям | Диагностика курса |
| `MSP2_SENSOR_BAROMETER` | Давление и температура | Высота и состояние барометра |
| `MSP2_SENSOR_AIRSPEED` | Дифференциальное давление и температура | Воздушная скорость |
| `MSP2_SENSOR_HEADTRACKER` | Данные головного трекера, если устройство поддерживается | Управление направлением камеры |
| `MSP2_INAV_TEMPERATURES` | Температуры доступных датчиков | Перегрев платы, ESC или двигателя |

## Ограничения совместимости

Классический `MSP_STATUS`, `MSP_ANALOG` и часть других старых сообщений в
актуальном исходном коде INAV помечены устаревшими; для них предусмотрены
современные MSP2-замены. Поэтому на Orange Pi лучше закладывать выбор протокола
по версии API и не смешивать поля разных форматов.

Точный состав полей и их порядок нужно брать из исходников той версии INAV,
которая прошита в конкретный полётник. Официальные каталоги сообщений:

- [MSP protocol definitions](https://github.com/iNavFlight/inav/blob/master/src/main/msp/msp_protocol.h)
- [INAV MSPv2 commands](https://github.com/iNavFlight/inav/blob/master/src/main/msp/msp_protocol_v2_inav.h)
- [MSPv2 sensor message structures](https://github.com/iNavFlight/inav/blob/master/src/main/msp/msp_protocol_v2_sensor_msg.h)
- [INAV MSP implementation](https://github.com/iNavFlight/inav/blob/master/src/main/fc/fc_msp.c)

## Паспорт объекта `telemetry`

Это отдельная справка именно для переменной, которую программа получает так:

```python
telemetry = inav_reader.update()
```

Тип результата — `InavTelemetry`. Объект хранит последние известные значения,
полученные от полётника. Он обновляется постепенно: в одном пакете может прийти
ориентация, в другом — GPS, в третьем — батарея. Поэтому значение может быть
старым, а поле, которое ещё ни разу не пришло, будет равно `None`.

### Все поля объекта

| Поле | Тип | Единица или формат | Что означает и зачем нужно |
|---|---|---|---|
| `telemetry.variant` | `str` | Текст | Вариант прошивки, обычно `INAV`. Нужен для проверки контроллера |
| `telemetry.version` | `str` | `major.minor.patch` | Версия прошивки INAV. Нужна для совместимости форматов |
| `telemetry.api_version` | `str` | `major.minor` | Версия API MSP. По ней можно выбирать поддерживаемые сообщения |
| `telemetry.roll` | `float | None` | Градусы | Крен влево/вправо. Нужен для наклона горизонта и индикации крена |
| `telemetry.pitch` | `float | None` | Градусы | Тангаж вверх/вниз. Нужен для смещения горизонта |
| `telemetry.yaw` | `float | None` | Градусы | Курс или угол рыскания. Нужен для компаса и направления |
| `telemetry.altitude` | `float | None` | Метры | Высота по барометру или оценке INAV |
| `telemetry.voltage` | `float | None` | Вольты | Напряжение батареи. Нужен для предупреждения о разряде |
| `telemetry.rssi` | `int | None` | Внутренняя шкала INAV | Сила сигнала приёмника. Для экрана преобразуется в проценты |
| `telemetry.gps_fix` | `int | None` | Числовой статус | Есть ли GPS-фикс и какого он типа |
| `telemetry.gps_satellites` | `int | None` | Количество | Число видимых или используемых спутников |
| `telemetry.latitude` | `float | None` | Десятичные градусы | Географическая широта. Нужна для карты, записи маршрута и Home |
| `telemetry.longitude` | `float | None` | Десятичные градусы | Географическая долгота. Нужна для карты, записи маршрута и Home |
| `telemetry.mode_flags` | `int | None` | Битовая маска | Набор активных режимов полёта, пока не расшифрован по отдельным флагам |
| `telemetry.armed` | `bool | None` | Логическое значение | `True`, когда полётный контроллер вооружён; `False`, когда разоружён |
| `telemetry.arm_switch` | `bool | None` | Логическое значение | Положение назначенного в INAV тумблера ARM независимо от разрешения на вооружение |
| `telemetry.arm_aux_channel` | `int | None` | Номер AUX | AUX-канал, на который назначен режим ARM |
| `telemetry.arm_switch_value` | `int | None` | Микросекунды RC | Текущее сырое значение ARM-тумблера |
| `telemetry.rc_channels` | `tuple[int, ...]` | Микросекунды RC | Снимок всех доступных каналов приёмника |
| `telemetry.throttle` | `int | None` | Микросекунды RC | Сырое положение канала газа, обычно в диапазоне 1000–2000 |
| `telemetry.throttle_percent` | `int | None` | Проценты | Положение газа, приведённое к диапазону 0–100 для OSD |
| `telemetry.updated_at` | `float` | Секунды `monotonic` | Время последнего принятого MSP-пакета. Нужно проверять свежесть данных |

### Как читать поля безопасно

Поля с типом `float | None` или `int | None` могут быть недоступны. Перед
использованием нужно проверять их наличие:

```python
if telemetry.altitude is not None:
    altitude_text = f"ALT {telemetry.altitude:.1f} m"
```

Для нескольких связанных значений проверяются все поля:

```python
if telemetry.latitude is not None and telemetry.longitude is not None:
    position_text = f"GPS {telemetry.latitude:.6f} {telemetry.longitude:.6f}"
```

Нулевое значение и `None` — не одно и то же:

- `None` — значение ещё не получено или датчик не отдаёт его;
- `0` — полётник действительно сообщил нулевое значение или нулевой статус;
- пустая строка — текстовое значение ещё не принято.

### Методы, связанные с объектом

Сам объект `telemetry` — это контейнер данных, а не устройство связи. У него
нет метода `telemetry.update()` и он сам не обращается к USB-порту.

| Объект и метод | Что делает |
|---|---|
| `inav_reader.update()` | Читает ответы, отправляет следующий безопасный запрос чтения и возвращает тот же объект телеметрии |
| `inav_reader.close()` | Закрывает USB-порт INAV |
| `inav_reader.telemetry` | Прямая ссылка на текущий объект `InavTelemetry` внутри читателя |

Правильная схема работы:

```python
telemetry = inav_reader.update()
print(telemetry.roll)
print(telemetry.pitch)
print(telemetry.voltage)
```

### Что сейчас реально обновляет объект

В текущем режиме читатель циклически запрашивает семь групп данных:

| Группа | Какие поля обновляет |
|---|---|
| Ориентация | `roll`, `pitch`, `yaw` |
| Высота | `altitude` |
| Высота над поверхностью | `surface_distance` |
| Аналоговая телеметрия | `voltage`, `rssi` |
| GPS | `gps_fix`, `gps_satellites`, `latitude`, `longitude` |
| Каналы RC | `throttle`, `throttle_percent` |
| Статус, диапазоны и ID режимов | `mode_flags`, `armed`, `arm_switch`, `arm_aux_channel` |

`variant`, `version` и `api_version` запрашиваются при открытии соединения.

### Что можно добавить в объект позже

Если расширить модель данных, в `telemetry` логично добавить следующие поля:

| Будущее поле | Типичный смысл |
|---|---|
| `gps_speed` | Скорость относительно земли |
| `gps_course` | Курс движения относительно земли |
| `gps_hdop` | Горизонтальная точность GPS |
| `home_distance` | Расстояние до точки Home |
| `home_direction` | Направление на Home |
| `current` | Ток батареи в амперах |
| `power` | Потребляемая мощность в ваттах |
| `mah_drawn` | Израсходованная ёмкость |
| `battery_percent` | Процент оставшейся батареи |
| `link_quality` | Качество радиоканала |
| `link_snr` | Отношение сигнал/шум |
| `flight_time` | Время полёта |
| `active_modes` | Список активных режимов вместо битовой маски |
| `gyro_status` | Состояние гироскопа |
| `barometer_status` | Состояние барометра |
| `gps_status` | Состояние GPS-датчика |
| `rangefinder_distance` | Расстояние до поверхности |
| `optical_flow_quality` | Качество оптического потока |
| `airspeed` | Воздушная скорость |
| `wind_speed`, `wind_direction` | Оценка ветра |
| `temperature` | Температура платы, датчика или ESC |
| `esc_rpm` | Обороты ESC |

Таким образом, при выборе `telemetry` в редакторе сейчас доступны ровно поля
из таблицы `InavTelemetry`. Будущие значения сначала должны быть добавлены в
модель объекта, затем их можно будет использовать в OSD, журнале, звуковых
предупреждениях или логике обнаружения.
